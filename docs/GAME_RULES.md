## 5. 점수 계산

| 규칙 | 상태 | 비고 |
|---|---|---|
| 투척별 독립 정산: `ThrowScore = BasicScore × Multiplier` → `TotalScore`에 1회 합산 | 확정 | 기존 (베이직 풀 × 누적 배율) 방식 폐기. 투척마다 베이직·멀티플 재계산, 이전 투척 임시값 미누적 |
| ~~윷별 베이직 기준값~~ → 베이직 = 도착 칸 점수 + 완주 보너스 + 윷별 강화치(`basicBonus`) | 확정 | 18칸 말판 도입으로 변경 (8절). 윷 기본 베이직 10~50 폐기 |
| 윷별 멀티플: 도 ×2 / 개 ×3 / 걸 ×4 / 윷 ×5 / 모 ×6 | 확정 | GPT 지시값 (기존 타겟 적중 시 +1~+5 가산 방식 폐기) |
| 윷별 영구 스탯 강화 구조 (주술 대비) | 확정 | 런타임 `yutStats` 복사본 사용 — `UpgradeYutStat()`으로 강화 시 기본 데이터 오염 없음. 강화 UI 미구현 |
| 효과 적용 단계 기록 (`ScoreEffectStep`) | 확정 | 부적·방울·주술·피버 발동 연출용 — 원인/식별자/표시명/대상/연산(+·×)/전·후 수치/증가량/순서 기록 |
| 백도 기본 처리 방식 | 확정 | 보스 1~5: 이번 판 점수(`roundScore`) 차감 / 보스 6~10: 이번 판 점수 초기화 — 이전 판 확정분 불침범 (4절 참조). 차감량은 미확정 테스트값 |
| 보스 목표 점수 = 선택 보스 최대 HP (`GoalScore`) | 확정 | 테스트 보스 5명: 1000/2000/3000/4000/5000 (이름·수치 전부 임시). 말판 방식으로 점수 상승 → 밸런스 조정 대상이나 임의 변경 안 함 |
| 보스 잔여 HP = `Max(0, GoalScore − TotalScore)` | 확정 | HP는 0 미만으로 표시하지 않음 |
| 보스 클리어 조건: `TotalScore ≥ GoalScore` | 확정 | 달성 즉시 클리어 처리 (정산 연출 정상 종료 후) |
| 게임오버 조건: 관문당 3판 종료 후 목표 미달 | 확정 | |
| 보스 특수능력: 낙 확률 +2%p (현재 전 보스 공통) | 확정 | 퍼센트포인트 가산 (×102% 아님). 증가분은 일반 결과 5종에서 상대 비중 유지하며 비례 차감, 백도 불변, 합계 100% 유지, 재시작 시 중복 적용 안 됨 |
| 라운드 목표 점수 | 미확정 | 보스 HP가 목표 점수를 대체 — 별도 라운드 목표는 현재 없음 |
| 라운드별 점수 증가 곡선 | 미확정 | |

## 7. 타겟 및 피버 시스템 (Gemini 제안)

| 규칙 | 상태 | 비고 |
|---|---|---|
| 라운드 시작 시 타겟 윷 1개 선택 → 적중 시 추가 보상 | 확정 | 코드 구현됨 (사용자 승인) |
| 타겟 적중 시 투척 차감 없음 + 콤보 증가 | 확정 | 보너스 투척 무한 반복 가능성은 밸런스 테스트에서 계속 관찰 |
| 2연속 적중부터 이번 투척 멀티플에 콤보 배수 적용 | 검토 중 | 투척 정산 구조로 이식: `이번 투척 멀티플 × Min(콤보, 8)` — 구 기준(전체 누적 배율) 대비 산출 차이 있음, 확정 필요 |
| 비타겟: 콤보 초기화 / 백도: 점수 풀 초기화 | 검토 중 | 코드에 구현됨, 수치 감각은 플레이 테스트 후 재검토 |
| 안정형 8피버 vs 고위험 5피버 빌드 분화 | 검토 중 | |
| 피버 배수 상한 8 (8콤보 이상 보상 동일) | 확정 | `appliedFever = Min(feverCombo, 8)` |

> 주의: 해당 시스템은 5회 투척·방울 덱빌딩과의 밸런스 검증 전이며, 임의로 구현/확정하지 않는다.

## 8. 원형 말판 및 방울 이벤트

| 규칙 | 상태 | 비고 |
|---|---|---|
| 18칸 원형 말판, 10~180점(10 단위) 중복 없는 배치 | 확정 | 보스전 시작 시 무작위 셔플, 같은 보스전 3판 동안 고정, 재도전 시 재배치 |
| 윷 결과별 이동: 도 1 / 개 2 / 걸 3 / 윷 4 / 모 5칸 | 확정 | 시계방향, 마지막 칸 이후 첫 칸으로 순환. 도착 칸에서만 점수·이벤트 판정 |
| 말 시작 위치 = 칸 밖 시작점 | 확정 | 첫 도 → 첫 번째 칸 도착. 위치는 3판 동안 유지, 보스전 재시작 시 초기화 |
| 베이직 = 도착 칸 점수 + 완주 보너스 + 윷별 강화치 | 확정 | 칸 점수는 `baseScore + bonusScore` 분리 (칸 강화 아이템 확장용) |
| 완주 보너스 = 완주 횟수 × 10 | 확정 | 마지막 칸(인덱스 17) 도달·통과 = 1회 완주. 보스전 내 유지, 재시작 초기화 |
| 방울 칸 = 점수 칸의 추가 속성 | 확정 | 착지 시 정상 득점 + 이벤트 발동. 지나가기만 하면 미발동 |
| 방울 이벤트: 후보 3개 제시 → 1개 선택 | 확정 | 미선택 2개 미획득, 선택까지 진행 일시 정지 |
| 방울 이벤트 칸 수 2개 / 판당 1회 발동 / 임시 방울 판 종료 소멸 | 프로토타입 | `bellEventTileCount`로 조정 가능, 밸런스 테스트 후 변경 가능 |
| 방울 실제 효과·사용 방식 | 미확정 | 현재 이름/설명만 저장·표시. 가짜 효과 임의 추가 금지 |
| 백도·낙의 말 이동 규칙 | 미확정 | 현재 구현: 이동 없음 (일반 이동 규칙 임의 적용 안 함 — 확정 필요) |
| 기존 12장 방울 덱·6개 제시→3개 선택 구상 | 구상 | 이벤트 방울과 별개로 유지 — 삭제·대체하지 않음 |

## 변경 이력

### [2026-10-14 오후 - GPT 기획 / Devin 구현]

- 윷 결과 6종 → 7종 확정: 낙(Nak) 추가. 백도·낙을 저주(Curse) 계열로 분류
- 백도 처리 확정: 보스 1~5 현재 판 점수 차감 / 보스 6~10 현재 판 점수 풀 초기화 (차감량은 미확정 테스트값)
- 낙 처리 확정: 획득 점수 0, 투척 1회 소모, 누적 점수 유지
- 확률 테스트값 조정: 낙 5% 신규, 개 37.5→32.5 (합계 100% 유지 — 임시값, 확정 아님)
- 타겟 선택 대상: 일반 결과 5종만 허용 확정 (백도·낙 제외)
- 저주 빌드 확장 예정(미구현): 낙→보상 전환 부적, 백도 방어 방울, 저주 배수, 저주 확률 조작 주술 — `IsCurse` 판별 구조만 마련
- 점수 정산 구조 확정: 투척별 독립 계산 `ThrowScore = BasicScore × Multiplier` → `TotalScore` 1회 합산 (풀×배율 누적 방식 폐기)
- 윷별 멀티플 변경 확정: 도 ×2 / 개 ×3 / 걸 ×4 / 윷 ×5 / 모 ×6 (기존 타겟 적중 +1~+5 가산 방식 폐기)
- 윷별 영구 스탯 강화 구조 확정 (주술 대비 런타임 스탯, 강화 UI는 미구현)
- 효과 적용 단계 기록 구조 (`ScoreEffectStep`/`ThrowSettlement`) 확정 — 부적·방울·피버 발동 연출의 데이터 기반
- 피버 적용식 이식(검토 중): 이번 투척 멀티플 × Min(콤보, 8) — 전체 배율에서 투척 멀티플로 변경되어 산출 차이 발생, 수치 확정 필요
- 보스전 구조 확정: 관문당 3판 × 판당 5회, 목표 점수 = 보스 HP, `TotalScore ≥ GoalScore` 클리어 / 3판 종료 미달 게임오버, 클리어·게임오버 패널 + 다시 도전·보스 선택 복귀
- 테스트 보스 5명 추가 (첫~다섯 번째 저승지기, HP 1000~5000) — 이름·수치 전부 임시값. 공통 특수능력 낙 +2%p (일반 5종 비례 차감, 백도 불변) — 보스별 다른 능력 대비해 데이터 분리
- 백도 차감 범위 실체화: 이번 판 누적(`roundScore`)만 차감/초기화 — 이전 판 확정분 불침범
- 보스 선택은 StartPanel 내부 UI로 확정 (5명 전부 직접 선택, 잠금·보상 미구현)
- 18칸 원형 말판 도입 확정: 10~180 중복 없는 랜덤 배치(보스전 시작 시, 3판 고정), 도착 칸 점수가 베이직, 윷별 이동 1~5칸, 완주 ×10 보너스 — 기존 윷 기본 베이직 10~50 폐기, 멀티플 2~6 유지
- 방울 이벤트 칸(점수 칸 추가 속성) + 3개 제시·1개 선택 + 판 한정 임시 방울 확정. 칸 수 2개·판당 1회는 프로토타입 설정
- 보고 필요 사항: 백도·낙 이동 규칙 미확정(현재 이동 없음으로 구현), 방울 실제 효과 미구현(이름/설명만)

### [2026-10-14 오전 - Gemini & Devin]

- 피버 배수 상한 8 확정: 곱연산에 적용되는 피버 보너스를 최대 8로 제한 (`Mathf.Min(feverCombo, 8)`), 8콤보 이상 보상 동일
- 타겟 적중 시 투척 차감 없음 + 콤보 증가, 2연속 적중 시 콤보 배수 적용 — 구현 동작을 사용자 승인으로 '확정' 승격
- 문서 기록 형식 변경: 세션별 `### [날짜 오전/오후 - 담당 AI]` 헤더 도입
